# Trace admin analytics

Open `https://www.yourtrace.online/admin/analytics`. The page verifies the signed, HTTP-only admin cookie before loading any metrics. The JSON, live and favicon endpoints verify the same cookie. Set a distinct `ANALYTICS_PASSWORD` and `ANALYTICS_SECRET` in the root-owned `/etc/trace/web-runtime.env` and restart `trace-web` after rotation. Rotate the signing secret to invalidate all existing sessions.

The Visitors and Speed tabs are a port of StocksBrew's first-party analytics (same panels, same math). The beacon (`lib/analytics/beacon.ts`) uses no cookies or account identifiers. It sends pageviews and a short list of key events (newsletter signup, sign-in started and finished, account made, onboarded, story clicked, summary opened, saved, shared, daily email switched, newsletter customized, sponsor checkout opened, purchase), each with at most one cleaned property such as the signup form or share channel. Only public pages leave the browser: a page that is the same for everyone (a blog post, a day's brief, a shared story) keeps its real path, a sponsor's stats page keeps only its route, and any other page sends nothing (`lib/analytics/normalize.ts` publicPath). It also sends the referrer's origin and the page's UTM tags on a visit's first pageview, the screen width, a signed-in yes/no flag and a random session id kept in sessionStorage for 30 idle minutes. The server drops bots and forged browsers (Lightpanda, or Chromium client hints that disagree with the User-Agent), resolves the country from Cloudflare or the shared DB-IP Lite file, and hashes the visitor address and user agent with a new random salt each UTC day. The address and user agent are never stored. Newsletter, account, checkout and purchase events keep only the minute and no session id. A visitor returning on two different days contributes to both daily counts. Live now reads the last five minutes of raw events.

Node 22's built-in SQLite keeps everything on disk under the service's private `/var/lib/trace-web-analytics` (`TRACE_ANALYTICS_DIR`), one file for production hosts and one for everything else (`lib/analytics/store.ts`). Events flush every five seconds as one raw chunk; page-load timings every minute. Every finished UTC day is folded into one rollup row (`daily`, `speed_daily`), and raw chunks are deleted five days after their day once that rollup is final. The queue holds at most 5,000 events, retries failed writes, and is spooled to a file on SIGTERM so a restart keeps it. Reads are capped (50,000 raw events a day) to stay inside the service's memory. The first version's tables (`totals`, `timings`, `seen`) are kept and no longer written: the dashboard adds their daily totals onto the days they cover, so history from Nov 21 stays. Those days have visitors, pageviews by route, sources, countries, devices and whole-site timings only; visits, bounce, campaigns, browsers and key events are blank for them, and their hourly counts are spread evenly. `seen` rows still expire after five days. On Nov 23, the day the new beacon shipped, visitor counts are slightly double-counted: the old and new tables hash visitors differently, so one person can appear in both.

The Signups and System tabs read one snapshot, `/var/lib/trace-analytics-snapshot/latest.json`, which `backend/vps/trace-analytics-snapshot.py` rewrites every five minutes (`trace-analytics-snapshot.timer`, `TRACE_ANALYTICS_SNAPSHOT` points the app at a local copy). It carries full emails, names and photo links, like StocksBrew's own Signups list, so it is owner-only: root-owned, group `trace-web`, mode 640, read only by the admin page after the cookie check (never commit or copy it outside a private scratch folder). Signups joins Firebase Auth (listed over REST with `/etc/trace/web-firebase.json`), `user_profiles` and `free_newsletter_subscribers` by email: everyone newest first (500 kept), with today, 7 and 30 days in UTC, newsletter readers (opted-out ones count in all signups), accounts and how many came back, readers' links and paid plans. System (`ops`) has the shape of StocksBrew's `tm_ops_health`: probes of the web app on 127.0.0.1:3817, Trace's LocalDB and the public site through Cloudflare, the daily brief and pipeline, Trace's Caddy log, 24 hours of Trace jobs from the journal (system and the ubuntu user's units), timers, LocalDB backups, and the box's memory, swap, disks and load copied from StocksBrew's own run so both tabs agree. A rolling 24-hour check history is kept in `ops-history.json` (root only). Each part fails soft, and the run keeps to a 90-second budget.

The script runs as root and runs only root-owned code: install it with `sudo install -o root -g root -m 755 backend/vps/trace-analytics-snapshot.py /usr/local/lib/`, and StocksBrew's checker it reuses as `sudo install -d -o root -g root -m 755 /usr/local/lib/trace-analytics && sudo install -o root -g root -m 644 <stocksbrew>/backend/ops/health.py /usr/local/lib/trace-analytics/sb_health.py`, from a checked-out copy, never from `/opt/tikrr` (the ubuntu user can write there). It refuses a module that root doesn't own or others can write. Reinstalling is how that copy is refreshed. Then install the unit, `daemon-reload` and `systemctl start trace-analytics-snapshot.service` once.

Trace's Caddy access log is `/var/log/caddy/trace.log` (since Nov 23): the `log` block under `db.yourtrace.online` in `/etc/caddy/Caddyfile` (backup `Caddyfile.bak-20261123-tracelog`) writes only `/_trace_web/*` requests, with addresses masked and the origin key, cookies and auth headers dropped. The System tab's requests, server errors and p50/p95 come from it.

Speed shows real full-page loads (reported on hide or client navigation) as Core Web Vitals histograms per route and device, with Caddy's time to upstream response headers as the Server p95 tile. Caddy adds the trace-origin Server-Timing entry, and the Worker removes it from edge cache hits.

Updates to the Next release, Caddy timing header and Worker assets follow the deployment procedure in `frontend/cloudflare/README.md`. Verify signed-out access first, then use the Worker preview hostname to exercise the live beacon without adding to production metrics.
